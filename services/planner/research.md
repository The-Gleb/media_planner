# Research: MediaPlan Optimizer — готовые решения и что важно

Обзор опен-сорса, коммерческих сервисов и алгоритмов под кейс «Media Planning & Optimisation Tool» (МТС AI). Собрано веб-ресёрчем, ссылки проверены.

Кейс делится на три модуля — планировщик, симулятор мира, сервис исполнения — плюс веб-кабинет. Ниже что тащить из готового под каждый.

---

## 1. Планировщик: MMM-библиотеки и оптимизация бюджета

Готовых медиапланеров под ключ в опене нет, но есть зрелый пласт marketing-mix-modeling (MMM), откуда берётся нужная механика: кривые отклика канала и оптимизатор распределения бюджета.

**Ключевой паттерн.** Отклик строится в две ступени: adstock/carryover (перенос эффекта во времени) + saturation (насыщение, убывающая отдача). Для насыщения повсеместно берут функцию Хилла:

```
response(spend) = spend^S / (spend^S + K^S)
```
где `K` — точка полунасыщения, `S` — форма кривой (S-образная или вогнутая).

| Библиотека | Язык / лиц. | Оптимизатор бюджета | Задачи A и B | Комментарий |
|---|---|---|---|---|
| **PyMC-Marketing** | Python, Apache-2.0 | `BudgetOptimizer` → `scipy.optimize.minimize(SLSQP)`, сумма-бюджет + границы по каналам | A есть; B через кастомный constraint | Самый гибкий; компоненты `HillSaturation`, `MichaelisMentenSaturation`, `GeometricAdstock` |
| **Meta Robyn** | R, MIT | `robyn_allocator()` | `max_response` = задача A, `target_efficiency` = задача B (мин. бюджет под CPA/ROAS) | Буквально ваши две постановки (имена сценариев сверены с исходником `allocator.R`) |
| **Google Meridian** | Python (TF Prob), Apache-2.0 | `BudgetOptimizer`, `fixed_budget=True/False` (+`target_roi`) | A и B | Сменил LightweightMMM (репозиторий заархивирован). Тяжёлый, для хакатона избыточен |
| **mamimo** | Python, лицензия не указана | нет | — | Крошечные sklearn-трансформеры насыщения/adstock. Репозиторий переехал в `RobKuebler/mamimo`, не обновлялся с 2023. Брать как референс паттерна, не как зависимость |
| **Uber Orbit** | Python, Apache-2.0 | нет | — | Байесовские тайм-серии, не про бюджет |

**Вывод для планировщика:** не тащить тяжёлый байесовский MMM. Хватает кривой Хилла на канал + `scipy.optimize.minimize(SLSQP)` с ограничением суммы и границами по каналам, либо жадный water-filling (лить бюджет туда, где выше предельная отдача на рубль). Задача B — та же с перевёрнутой целью или бинарный поиск по бюджету, т.к. отклик монотонен по расходу. Недостижимость: упереться в асимптоту кривой и вернуть «цель недостижима, максимум достижимого = X», а не пустой ответ.

## 2. Симулятор мира и сервис исполнения

### Симулятор (референсы, не база)
- **AuctionGym** (Amazon, Apache-2.0) — симуляция аукционов показ→клик→конверсия, конфиг JSON, детерминизм по seed. Смотреть структуру конфигов.
- **RecoGym** (Criteo), **RecSim / RecSim NG** (Google) — Gym-среды для рекомендаций/рекламы.
- **iPinYou / optimal-rtb** (wnzhang, Apache-2.0) — RTB-датасет и бенчмарк-фреймворк ставок (KDD'14). Для вдохновения по win-rate кривым.
- **rlrtb** (`MTSWebServices/rlrtb`) — это подборка статей от МТС про RL в RTB плюс примеры симулятора аукциона, RL-агентов и обработанный сэмпл iPinYou. Не готовый симулятор, а учебный репозиторий. Полезен как сигнал, на что смотрит кейсодатель.

### Модели охвата (брать напрямую)
Цепочка `spend → показы → уникальный охват → клики → конверсии`:

1. **Spend → показы:** `impressions = spend / eCPM`, eCPM растёт с выкупом ёмкости через логистическую win-rate кривую → это «рост цены при выкупе».
   ```
   eCPM(t) = floor + (cap - floor) / (1 + exp(-k*(demand_share - 0.5)))
   ```
2. **Показы → уникальный охват:** негативно-биномиальная модель Эренберга (NBD) либо бета-биномиальная (Sainsbury / Metheringham). Убывающий предельный охват:
   ```
   reach ≈ N * (1 - (k/(k+λ))^k)    # λ = средняя частота
   ```
3. **Насыщение охвата по бюджету:** обернуть кривую в Хилла (уплощается на больших бюджетах, как Google Reach Planner).
4. **Клики/конверсии:** `clicks = impressions * CTR(freq)`; базовые CTR/CR из Beta, CPM из log-normal, калибровать под публичные бенчмарки.
5. **Детерминизм:** отдельный `numpy.random.Generator` на пару (канал, час) с хешем от seed. Ровно ваши два seed: каталог и шум кампании.

**Анти-утечка:** слой каталога (публичные кривые для планировщика) и слой мира (истинные параметры) генерируются раздельно, каждый от своего seed. Каталог — намеренно зашумлённая/смещённая версия истины, чтобы факт честно расходился с прогнозом.

### Сервис исполнения — pacing-контур
Литература по budget pacing ложится прямо на «держать факт у плановой траектории»:
- **Throttling / smooth delivery** (Google, ADKDD 2013) — базовый темп через вероятность участия.
- **Smart Pacing** (Yahoo, KDD 2015) — обратная связь подстраивает темп по отклонению от плана.
- **PID + mini-MPC** — признанный дешёвый и робастный вариант, отлично показывает реакцию на шок. **← брать это.**
- **Двойственный / Lagrangian pacing** (mirror descent, water-filling по каналам) и **RL (DRLB, CIKM 2018)** — теоретический потолок, для 4 дней избыточно.

Рекомендованный почасовой контур:
```
plan = allocate_budget(total_budget, hours)      # стартовый план
spent_cum = 0
for hour in range(hours):
    obs = observe(spent_cum, ctr, cpm)           # факт за час
    remaining_budget = total_budget - spent_cum
    # переаллокация остатка по прогнозной предельной ценности (реакция на причину шока)
    plan[hour:] = reallocate(remaining_budget, hours - hour, forecast(ctr, cpm),
                             channel_min, channel_max)
    plan_cum = cumsum(plan)                      # плановая накопительная траектория
    error = plan_cum[hour] - spent_cum
    integral += error; deriv = error - last_error
    mult = clip(1 + Kp*error + Ki*integral + Kd*deriv, 0.3, 3.0)   # PID сглаживает
    spend = execute(bid_multiplier=mult, target=plan[hour])
    spent_cum += spend; last_error = error
```
Связка «переаллокация + PID» обгоняет замороженное распределение после скачка CPM / падения CTR. **Метрика — MAPE накопленных spend и KPI к концу кампании** (совпадает с кейсом). Обязательны лимиты min/max по каналу.

## 3. Коммерческие сервисы и что важно продукту

Все крупные платформы — одна петля `бриф → прогноз → согласование → запуск → мониторинг → перераспределение`. Кейс её повторяет.

**Прогнозаторы плана**
- **Google Reach Planner** (бюджет → охват/частота/конверсии), **Performance Planner** (цель CPA/ROAS → бюджет, what-if слайдеры).
- **The Trade Desk Planner** — кросс-канальный прогноз охвата.
- **Meta CBO / Advantage+** — динамическая переаллокация внутри бюджета; ломает предсказуемость pacing, поэтому ставят min/max по строкам.

**План против факта**
- **Mediaocean Prisma** — эталон сверки plan-vs-actual с правилами на отклонение.
- **Nielsen ONE** — планирование + in-flight оптимизация.

**Российские (особенно релевантны)**
- **VK Ads «Прогнозатор»**, **myTarget** — прогноз охвата по бюджету/ставке.
- **Click.ru** — обратный счёт «задай число кликов → подберём бюджет и ставку». Это в точности задача B, которой нет у Google/Яндекса.
- **eLama**, **Aori** — операционные хабы бюджета и автоправила ставок.

**Must-have для UI (жюри узнает эти паттерны)**
- **Два входа на выбор** — бюджет ИЛИ цель KPI → получаешь второе. Ваши A и B как один переключатель.
- **Кумулятивный график доставки** — плановая линия против фактической. Центральный экран мониторинга.
- **Один индикатор темпа** — «+23% впереди / −7% позади», цветом.
- **What-if пересчёт** — меняешь бюджет/срок/цель → прогноз пересобирается мгновенно.
- **Ограждённая автоматика** — автоперераспределение обязано иметь границы min/max по каналу, иначе нет доверия.

## Итог для прототипа
- **Планировщик:** Хилл-кривые на канал + SLSQP или жадный water-filling; тип B через бинарный поиск по бюджету; честная диагностика недостижимости.
- **Симулятор:** NBD-охват + логистический рост eCPM + Хилл-насыщение; всё на seed; каталог и мир раздельно (анти-утечка).
- **Исполнение:** PID поверх почасовой переаллокации, лимиты по каналам, метрика MAPE.
- **UI:** переключатель A/B, кумулятивный план-факт, индикатор темпа, what-if.
- Ничего не требует GPU, укладывается в «секунды на ноутбуке».

### Объём рынка (АРИР, сверено с публикациями Sostav)
- 2024: ₽1.236 трлн (+53% г/г).
- 2025: ₽1.569 трлн (+28% г/г). Сегменты 2025: еРетейл медиа ₽580 млрд (+58%), перформанс ₽471 млрд (+8%), классифайды ₽226 млрд (+19%), брендинг ₽162 млрд (+33%), инфлюенс ₽57 млрд, мессенджеры ₽24 млрд, мобильные операторы ₽38 млрд.
- Рост замедляется (53% → 28%), драйвер — маркетплейсы.

### Нюансы вариативности (закладывать в мир)
- **Формат:** поиск CTR/CPC ≫ сеть/дисплей (РФ поиск CPC ₽47 против сети ₽11); PMP CPM в 2–3× выше open exchange.
- **Таргетинг:** lookalike / first-party ~×10 CTR против generic display; ретаргет ≫ prospecting.
- **Сезонность:** колебания CTR до ±100% и CPM ±30% квартал к кварталу; Q4/праздники — пик CPM.
- **Час суток:** публичных РФ-данных нет. B2B — дневные пики, B2C/соцсети — вечерние. Это модельное допущение, не источник.

**Осторожно:** самые надёжные РФ-числа — исследование click.ru на Habr (Яндекс Директ / VK / myTarget / Avito, окт-2023 → окт-2024, публикация дек-2024), таблицы выше сверены с первоисточником. Цифры АРИР сверены с Sostav. По маркетплейсам (в т.ч. «мин. ₽7/клик на Ozon») и SMS публичных бенчмарков меньше и они не перепроверены — берите шире диапазоны и середины.

**Как использовать в симуляторе:** это диапазоны для стартовых параметров базовых CPM/CTR/CR на канал (log-normal для CPM, Beta для CTR/CR), из середины ± сезонный и почасовой множители. Каталог для планировщика — намеренно смещённая/зашумлённая версия этих же диапазонов.
