## 2. Боль и её цена

**Тезис:** оба шага сейчас ручные, и ошибка в 10–15 % бюджета стоит 120–180 тыс. ₽ на одной кампании.

- Две роли: медиапланер обещает KPI и защищает распределение; трафик-менеджер удерживает факт у плана.

## 4. Ключевые решения

**Тезис:** утечка скрытых параметров исключена по построению, а трекер минимизирует отклонение, а не гонится за KPI.

1. Два независимых сервиса с HTTP-контрактом: симулятор на Go (stdlib, порт 8080), планировщик и трекер на
   Python (порт 8501). Симулятор ничего не знает о планировщике.
2. Анти-утечка: планировщик видит только диапазоны из конфига мира; конкретные значения симулятор сэмплит по seed
   и наружу не отдаёт. Мир проявляется только через почасовые пакеты.
3. Один и тот же механизм насыщения (рост цены, усталость CTR, падение доли новых пользователей) и в мире, и в
   ожидаемой модели планировщика, но планировщик считает его по серединам публичных диапазонов.
4. Цель трекера — минимум отклонения от утверждённого плана. Отстали — калибруемся и переоптимизируем остаток;
   идём по плану — не трогаем распределение.
5. Два seed (мир и кампания), независимые keyed-потоки случайности: замена одного канала не меняет другие.

## 5. Схема решения

**Тезис:** одна картинка контура.

```
world-config.json (публичные диапазоны 8 каналов)
   ├─► catalog (середины диапазонов + суточный профиль)
   │       └─► planner: кривая «дневной бюджет → KPI» → жадное распределение → MediaPlan (бюджет по каналам и часам,
   │                                                                              плановые траектории spend и KPI)
   └─► Go-симулятор: сэмплит скрытый мир по world_seed
           PUT /v1/simulations/{id}      reset: seeds, горизонт, scenario_events
           POST /v1/simulations/{id}/steps   час: лимиты по каналам → пакеты по каналам
                   └─► executor: frozen | adaptive  ─► metrics: отклонение и MAPE spend / KPI
```

- Показать: схему как диаграмму, справа — стек и порты, снизу — `docker compose up --build --wait`.

## 6. Модель мира и симулятор

**Тезис:** правдоподобный, воспроизводимый и управляемый рынок за секунды.

- 8 каналов: 3 соцсети, programmatic, 3 маркетплейса, SMS. Базовые CPM и спрос — log-uniform, CTR и CR —
  logit-uniform в диапазонах публичных бенчмарков (например, маркетплейс: CPM 230–390 ₽, CTR 1,5–2,7 %, CR 6–10,5 %).
- Почасовые пики спроса, цены, CTR и CR (1–2 пика, центр и ширина случайны), недельная сезонность с модификатором
  выходных.
- Насыщение: порог старта, квадратичный рост цены, усталость CTR по глубине выкупа и частоте, падение доли новых
  пользователей. Волатильность requests и CPM — log-normal шум по часам.
- События: случайные дрейфы и шоки по seed кампании, плюс управляемые сценарии для стенда (ctr / cpm / supply /
  pause, канал, час старта, длительность, множитель).
- Деньги — int64 микроединицы, spend никогда не превышает лимит. ETag и step_id: шаг безопасно повторяем.
- Проверки: 44 Go-теста, включая golden-прогон, fuzz и бенчмарк.
- Показать: таблицу диапазонов по каналам и один график суточного профиля.

## 7. Планировщик, задача A

**Тезис:** план строится на кривой отклика, а не на средних CPM, поэтому он достижим.

- Каталог = середины публичных диапазонов + ожидаемый суточный профиль.
- Для каждого канала — ожидаемая динамика по дням при фиксированном дневном бюджете: показы упираются в спрос,
  цена растёт с выкупом, CTR устаёт. Получается точечная кривая «дневной бюджет → KPI за кампанию».
- Распределение жадное: следующий ломтик бюджета уходит в канал с наибольшим приростом KPI на рубль.
- Выход: бюджет по каналам и часам, календарь расходов, плановые траектории spend и KPI, таблица CTR, CR, CPM,
  CPC, CPA.
- Показать: таблицу демо 1 (слайд 9) и кривые отклика по каналам.

## 8. Сервис исполнения

**Тезис:** трекер держит темп по плану и переоптимизирует остаток только когда отстал.

- Бейзлайн frozen: каждый час тратим ровно по плану, распределение не меняется.
- Adaptive: множитель темпа расхода на остаток бюджета относительно плановой траектории.
- Калибровка каталога по факту: CTR и CR по окну 72 ч с усадкой к каталогу через псевдонаблюдения (сырые часовые
  отношения слишком шумные), eCPM — сглаженное отношение факт/прогноз.
- Переоптимизация остатка раз в 6 часов, если накопленный KPI отстал от плана больше чем на 2 %.
- Каналы плана всегда получают разведочные 10 % часового расхода, чтобы не выпадать из наблюдений.
- Показать: схему «час → пакет → калибровка → решение», график перераспределения из песочницы.

## 11. Ограничения и открытые вопросы

**Тезис:** мы знаем, где прототип слабый, и это входит в план.

- Задача B не реализована, демонстрация 2 (50 000 кликов за 14 дней, диагностика) пока не показывается.
- Выигрыш адаптива при CTR-шоке скромный (1,4 п. п. по отклонению), заметный только при паузе канала.
- Трекер исправляет только отставание: при перевыполнении плана adaptive уходит от плана не меньше frozen
  (со случайными событиями мира +5,1 % против +4,4 %).
- Переоптимизация остатка не учитывает уже выкупленную аудиторию, оценка оптимистичная.
- unique_reach не дедуплицируется между каналами, охват кампании как сумма — нельзя. VTR нет, лимитов min/max по
  каналу нет.
- Веб-кабинет пока песочница для инженеров, а не интерфейс для бизнес-пользователя.
- Отчёт о выбранных распределениях и правиле перераспределения — только в README.
