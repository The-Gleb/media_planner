### Слайд 3. Постановка задачи
Тезис: автоматизировать распределение бюджета до запуска и его перераспределение каждый час после.
- Планировщик. Задача A: бюджет и горизонт → максимум кликов или конверсий. Задача B: целевой объём → достаточный бюджет или диагноз «недостижимо» с рекомендацией.
- Симулятор рынка с внутренним скрытым состоянием: восемь каналов, шаг один час, на выходе requests, impressions, unique_reach, clicks, conversions, spend, eCPM.
- Сервис исполнения: сверка накопленного факта с планом и перераспределение остатка на следующие часы.
- Метрика: MAPE накопленных spend и KPI относительно плана к концу кампании; порог 20 %; при шоке адаптив должен быть заметно ближе к плану, чем заморозка.

### Слайд 4. Выбранный подход
Тезис: прогноз по бенчмаркам и кривым отклика, коррекция плана каждый час по фактическим данным.
1. Прогноз строится на публичных диапазонах CPM, CTR, CR, их распределении по часам и дням и кривых отклика «бюджет → показы» с ростом цены при выкупе аудитории.
2. План — распределение по каналам и часам плюс плановые траектории spend и KPI.
3. Каждый час трекер сверяет факт с траекторией: держит темп расхода, а при отставании калибрует кривые отклика по наблюдениям и переоптимизирует остаток. Бейзлайн frozen кривые не корректирует.
4. Анти-утечка: планировщик видит только диапазоны, конкретные параметры мира сэмплятся симулятором по seed и наружу не отдаются.
5. Два независимых сервиса: симулятор на Go (порт 8080), планировщик и трекер на Python (порт 8501), один docker-compose.

### Слайд 5. Схема решения

### Слайд 7. Как считаем
Тезис: одна кривая отклика на всех уровнях и одно правило коррекции.
- Мир: параметры канала из диапазонов (CPM и спрос — log-uniform, CTR и CR — logit-uniform), почасовые и недельные профили, насыщение по доле выкупленной аудитории $z$: цена $P = 1 + g z^2$, усталость CTR $e^{-\alpha z}$, доля новых пользователей $(1-z)^{\rho}$. Показы $\min(\text{спрос},\ 1000B/\text{cpm})$, охват, клики и конверсии — биномиальные выборки.
- Планировщик: та же динамика по серединам диапазонов даёт кривую $K_c(b)$ «дневной бюджет → KPI за кампанию». Задача A: $\max \sum_c K_c(b_c)$ при $\sum_c b_c = B/D$, решается жадно — каждый ломтик бюджета уходит каналу с наибольшим приростом KPI.
- Трекер: если факт KPI отстал от плана больше чем на 2 %, CTR и CR калибруются по окну 72 ч с усадкой к бенчмарку, CPM — по отношению факт/прогноз, и остаток бюджета переоптимизируется раз в 6 ч; иначе расход ведётся по плановой траектории.
